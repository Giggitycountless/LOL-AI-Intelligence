### 3. 规范完善建议

**新增审查规则**

| 规则名称 | 严重度 | 说明 |
|---------|--------|------|
| **REACT-UNMOUNT-CLEANUP** | minor | 使用 ref 存储异步操作状态时，需在 `useEffect` 清理函数中重置，避免已卸载组件更新 |
| **ENV-POLYFILL-AMBIGUITY** | minor | 环境检测应明确“目标环境”而非“特征存在”，如检测到 `window.__TAURI__` 但实际为 polyfill 时需降级 |
| **TEST-ENV-DUAL** | minor | 测试应覆盖“正常环境”+“异常环境”两个维度，而非仅 mock 缺失场景 |

**项目特有规范补充**
- 所有“一次性守卫” ref 必须在组件卸载时清理（set to `false` 或 `null`），避免严格模式下重挂载时的状态残留
- 环境检测函数应返回三态：`'tauri' | 'web' | 'unknown'`，而非布尔值
- 新增环境检测逻辑时，必须同步更新 `docs/ENVIRONMENT.md` 说明各环境下的行为差异

### 4. 经验教训

**未来审查关注点**
1. **React 严格模式兼容性**：涉及 `useEffect` + ref 守卫的代码，检查是否假定只执行一次
2. **环境检测的完备性**：检查是否只做了“存在性检测”而非“能力检测”（如 `typeof invoke === 'function'` 的误导性）
3. **测试的双面性**：所有“fallback 测试”都应配套一个“正常路径测试”，确保 fallback 不会误伤正常场景

**对特定技术的审查经验**
- **Tauri + Vite**：`vite dev` 下 `__TAURI_INTERNALS__` 不存在，但 `invoke` 仍可通过 mock 注入，因此 `canInvokeDesktopBackend` 应仅依赖 `__TAURI_INTERNALS__`，忽略 `invoke` 类型检查
- **React ref 守卫**：在多轮增量审查中容易被忽略，因为它不直接引发错误，只在特定时序下暴露
