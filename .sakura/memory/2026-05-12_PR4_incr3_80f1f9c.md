## 4. 经验教训

### 未来审查关注点
1. **并行化代码必查连接池**：`rayon` + `reqwest` 容易忽略 `Client` 是共享还是每线程新建。
2. **迁移脚本必须回滚**：即使 MVP，也强制要求 `down` 以保持可逆性。
3. **类型安全降级**：前端将 `t` 函数收窄为 `(string) => string` 会丧失 key 校验，应视为 minor 问题。

### 特定技术审查经验
- **增量审查的盲区**：当历史关键问题被修复后，审查容易忽略**同一文件中其他未变更的旧问题**（如 Advisor.tsx 中的 lane 标签）。建议在增量审查模板中增加“同文件历史遗留项”检查项。
