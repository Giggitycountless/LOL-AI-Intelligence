### 3. 规范完善建议

基于本次审查，建议在项目的代码审查规范中增加以下规则：

#### 新增规则
1. **工具函数参数类型必须覆盖 `undefined`**  
   规则：任何接受 `number | null` 且从可选属性或 API 响应中获取值的函数，必须考虑 `undefined` 的可能性（建议使用 `value == null` 判断）。
   - 示例：`formatDuration(value: number | null | undefined)`

2. **测试用例必须验证其声称的场景**  
   规则：测试名称中的“特殊字符”、“边界条件”等描述，必须在输入中真实包含相应数据，否则应更名或修改输入。
   - 示例：测试“encodes special characters”时必须传入 `{ gameId: '#', participantId: '?' }` 等。

3. **异步 rejection 路径必须使用异步断言**  
   规则：对于返回 Promise 或内部有异步 rejection 的函数，不能使用 `expect(() => fn()).not.toThrow()`，而应用 `await expect(fn()).resolves.not.toThrow()` 或模拟 rejection 后验证副作用。

4. **行为变更必须明确标记并确认**  
   规则：当重构改变了函数对特殊输入值（如 `0`、`-1`、`''`）的返回结果时，必须在 PR 描述或评论中明确说明，并确认新行为符合产品预期。

#### 项目特有规范
- **Event listener 注册必须使用 `listenWithCleanup`**（或类似的统一封装），禁止直接裸用 `listen` 以避免 unhandled rejection。
- **React Effect 中如果依赖项会导致频繁重注册，优先考虑使用 ref + 回调模式**，如本次 `Matches.tsx` 的优化。
