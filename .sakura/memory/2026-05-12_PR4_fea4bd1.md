## 3. 规范完善建议

基于本次审查，建议新增或强化以下审查规则：

### 新增规则

| 规则 ID | 描述 | 严重程度 |
|---------|------|---------|
| **PERF-N+1** | 检测在轮询或循环中对每个实体发起多次顺序 HTTP 调用 | major |
| **ERROR-SILENT** | 检测 `if let Ok(_) = fallible_operation()` 且无日志记录 | major |
| **I18N-MISSING** | 新增 UI 组件中硬编码用户可见字符串 | minor（MVP） / major（正式版） |
| **MIGRATION-ROLLBACK** | 数据库迁移文件需提供 `down` 回滚脚本 | minor |

### 强化现有规则

- **并发安全**：检查并行化改造后是否存在连接池或共享状态竞争
- **Unmount 清理**：前端异步请求（`fetch`、`setTimeout`）是否在组件卸载时取消/清理
- **序列化兼容性**：JSON 存储结构必须包含 `version` 或 `schema_version` 字段

## 4. 经验教训

### 未来审查关注点（针对 Rust + Tauri + React 项目）

1. **轮询 × 串行调用**：任何 `setInterval`/轮询内的循环请求都应优先审查其并发模型。
2. **`if let Ok` 模式**：Rust 中静默失败极易隐蔽 bug，建议要求显式 `log::warn!`。
3. **前端 i18n**：在 project memory 中记录「新增页面必须使用 `t()`」的硬性约束。
4. **存储迁移**：`payload_json` 字段应强制要求伴随 `version` 字段。
